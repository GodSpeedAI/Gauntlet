## MAJOR findings

**M1. AK-028's evidence locator `tests/contract/observer::facet_provenance` does not exist anywhere in the repository.**
The frozen ruler (`.wayfinder/answer-key.md:193-198`) requires evidence `{kind: test_report, locator: tests/contract/observer::facet_provenance}`. The actual shared Observer contract suite (`/home/sprime01/projects/gauntlet/crates/gauntlet-ports/src/contract/observer.rs:137-142`) contains exactly two cases: `facets_name_their_own_kind` (line 55) and `failed_probes_are_errors_not_facets` (line 107). A repo-wide grep for `facet_provenance` returns nothing. AK-028's *substance* is tested — each of the five adapters has `a_facet_carries_full_provenance[_and_matching_evidence|_and_a_failing_exit_is_still_a_facet]` (e.g. `/home/sprime01/projects/gauntlet/crates/adapters/gauntlet-adapter-observe-build/tests/shared_contract.rs:169-230`, git at :186, filesystem at :199, test at :169, command at :173) — but under bespoke per-adapter test names, not as a contract-suite case at the ruler's locator. Given Gauntlet's own principle that evidence requirements are bindings (§9.6), an unfilled locator is a traceability defect even when the substance is present. Related, same class: AK-029's `tests/proofs/p3_real_observation` and AK-030's `tests/antigaming/g6_hide_failed_observations` are materialized as `crates/gauntlet-cli/tests/p3_real_observation.rs` and `crates/gauntlet-cli/tests/g6_hide_failed_observations.rs`, while the top-level `tests/proofs/` and `tests/antigaming/` hold only `.gitkeep`. That deviation is at least documented in-code with an architecture-boundary rationale and matches the pre-existing `p1_reference_integrity` precedent (`p3_real_observation.rs:6-15`, `g6_hide_failed_observations.rs:5-14`); the AK-028 case has no such recorded rationale and, unlike the proofs, it names a *contract-suite case name* that was simply never added.

**M2. The four subprocess adapters block unboundedly in time and capture unboundedly in memory; the `Deadline` parameter is not enforced on the child.**
`BuildObserver::observe` (`/home/sprime01/projects/gauntlet/crates/adapters/gauntlet-adapter-observe-build/src/lib.rs:133-140`), `TestObserver::observe` (`.../gauntlet-adapter-observe-test/src/lib.rs:133-140`), `CommandObserver::observe` (`.../gauntlet-adapter-observe-command/src/lib.rs:144-151`), and `GitObserver::observe` (`.../gauntlet-adapter-observe-git/src/lib.rs:114-121`) call `std::process::Command::output()` with no timeout and no output-size cap; the `deadline` parameter is only forwarded to the evidence-store write. The port itself states the purpose being skirted: `deadline.rs:10-13` — "an unbounded blocking call is exactly what this type exists to make unrepresentable at the call site." Spec §18.4 explicitly assumes "test hangs" as a failure the system must dispose of; a hung build/test command instead hangs `observe()` forever. Captured stdout/stderr also enter the `FacetEvidenceDoc` without any byte cap (contrast the filesystem adapter, which names and enforces depth/entry/byte caps at `.../gauntlet-adapter-observe-filesystem/src/lib.rs:50-59` precisely because of a prior runaway-memory lesson). The deferral is candidly documented in `assembly.rs:6-9` ("not enforced as process timeouts"), but candor does not bound the loop; this is the strongest AGENTS.md bounded-autonomy violation in the artifact.

**M3. P3's second clause — "comparison operates on it" — is not yet composed, and the current comparison envelope structurally cannot carry facet-level reality.**
`VerificationInputs` has zero consumers outside the observation module and the two CLI tests (repo-wide grep). The p3 proof substitutes assertions on the inputs' serialized form (`/home/sprime01/projects/gauntlet/crates/gauntlet-cli/tests/p3_real_observation.rs:303-315`) for an actual `ComparisonRecord` over the failing observation. The pre-existing `ComparisonEnvelope` (`/home/sprime01/projects/gauntlet/crates/gauntlet-ports/src/comparator.rs:47-61`) carries the *domain* `ObservationBundle`, which holds only digest + the two gap arrays (`/home/sprime01/projects/gauntlet/crates/gauntlet-domain/src/observation.rs:71-76`) — no facets, no exit statuses — so a comparator wired today could not see the recorded instrument failure at all. AK-029's frozen claim (claims excluded from verification inputs by construction) is fully proven; §23.1 P3's composed claim is only half-realizable, and the envelope (or `reference_view`) will need widening when comparison wiring lands. The artifact's own comments defer this to a later task (e.g. `mod.rs:34-37`, `assembly.rs:8-9`); as a blind critic I can verify the deferral's existence, not its plan-level legitimacy.

## MINOR findings

**m1. Spawn-failure error taxonomy is inconsistent across adapters for the identical failure mode.**
The port defines `InstrumentFailed` = "the instrument ran and failed" and `Unavailable` = "the instrument could not run at all" (`observer.rs:42-47`). Git maps spawn failure to `Unavailable` (`gauntlet-adapter-observe-git/src/lib.rs:118-121`); build, test, and command map the same `Command::output()` spawn error to `InstrumentFailed` (`gauntlet-adapter-observe-build/src/lib.rs:137-140`, `gauntlet-adapter-observe-test/src/lib.rs:137-140`, `gauntlet-adapter-observe-command/src/lib.rs:148-151`), and the g6 proof pins that choice (`g6_hide_failed_observations.rs:269-272`). By the port's own doc, a binary that fails to spawn "could not run at all." Downstream impact is nil today — `gap_entries_for` (`assembly.rs:221-242`) populates both gap arrays for either variant — but the recorded `error_class` token differs for the same locus, which erodes §21.2's diagnosability purpose.

**m2. The git adapter's nonzero-exit exception produces no facet and no content-addressed evidence for the failure.**
`gauntlet-adapter-observe-git/src/lib.rs:126-144` converts any nonzero git exit (e.g. a workspace that is not a repository) into `ObserverError::InstrumentFailed`, pinned by test (`tests/shared_contract.rs:234-253`). Judged **spec-consistent and conservative**: it is recorded (never dropped, never a pass) via both gap arrays, satisfying AK-030/§21.3; the exit code and stderr survive only inside the gap `detail` strings rather than as stored evidence bytes. Fail-closed; acceptable, but the failure's raw output is not forensically retrievable the way successful facets' output is.

**m3. "Instrument version" is the wrapper crate's version; the wrapped tool's identity/version is never probed.**
All five adapters record `INSTRUMENT_NAME` + `env!("CARGO_PKG_VERSION")` (e.g. `gauntlet-adapter-observe-git/src/lib.rs:146-148`, which documents "Git's own version is deliberately NOT probed"). §12.2 asks for "the instrument identity and version"; "the wrapper IS the instrument" is a defensible repo convention (documented at `observer_evidence.rs:4-15`), but the porcelain v1 output format varies across git versions, so reproducibility (§12.4) loses the wrapped binary's identity. Documented limitation, not a violation.

**m4. `ObservationPlan` identity strings are unvalidated at the construction path.**
`assembly.rs:64-71` exposes `project_revision` and `environment_fingerprint` as plain `pub String`s with no non-empty check, while strict decode of the produced document *does* require both non-empty (`bundle.rs:761-762`). An in-memory caller passing empty strings gets a bundle that fails its own wire contract. No production caller exists yet (grep), so this is latent.

**m5. An empty observer list assembles an "all-healthy" bundle with zero probes, and the request does not name the facets to collect.**
`assemble` iterates `plan.observers` with no emptiness or required-kind-set check (`assembly.rs:103-112`); an empty plan yields `facets: []` plus empty gap arrays — a positive attestation that nothing was unavailable, though nothing was observed. Relatedly, §12.2 says "An `ObservationRequest` names the facets to collect," but the pre-existing `ObservationRequest` (`observer.rs:68-73`) carries only run/iteration/workspace; facet selection lives in `ObservationPlan.observers` instead. The port was respected rather than modified (correct per task framing), but the spec-text deviation and the missing completeness cross-check are real.

**m6. The provenance cross-check compares exit status only.**
`assembly.rs:203-210`: a facet whose `exit_status` is `None` skips the check silently, and command/instrument-name agreement between the `FacetRecord` and its decoded `FacetEvidenceDoc` is never compared. Defense-in-depth gap only; nothing in the spec mandates the cross-check at all.

**m7. The type system permits an incomplete facet; enforcement is by convention plus per-adapter tests.**
`ObservationFacet::new` requires only kind + instrument + evidence ref (`observer.rs:92-103`); command, exit status, and the timing window are `Option`s settable to `None` (`observer.rs:107-122`), and the B.3 wire renders them as JSON `null` (`bundle.rs:266-283`, pinned by test at :1187-1189). Notably the spec's own invalidity clause singles out only identity ("A facet with no instrument identity is invalid," §12.2), and the artifact enforces exactly that split. All five Task-9 adapters populate every field (verified by reading each `observe()`), so this is latent, not active — but a future adapter could emit a `null`-command facet that neither the assembler nor the decoder would flag.

**m8. §12.4's "re-taken observation digests identically" holds only at the bundle-document level.**
`normalized_bytes` (`digest.rs:26-66`) implements the letter of §12.4 exactly (drop `observed_at` and per-facet `started_at`/`ended_at`, pin the self-referential digest field to `""`; nothing else excluded). But facet evidence bytes contain their own timestamps and run-varying output, are content-addressed, and therefore change the `evidence_ref` on every re-take — so the end-to-end digest still moves. Spec's "where practical" qualifier makes this acceptable; recorded for honesty.

**m9. Annex B.3 narrowings (all documented at `bundle.rs:12-16`), judged acceptable individually:**
- `summary` narrowed to `{}` or `{"text": str}` (B.3 shows an open `{}`).
- Timestamps are epoch-second integers, not strings (B.3 placeholders are `""`).
- `iteration_no` 0 — B.3's placeholder — is rejected by the 1-based domain `IterationNo` (`values.rs:439-447`; decode at `bundle.rs:724-733`).
- Gap-entry `kind` must parse against the 8-token `FacetKind` vocabulary (`bundle.rs:486, 547`), so §12.2's wider facet classes (lint/static, runtime_probe, logs, metrics, security_scan, external) cannot be recorded even as *unavailable* kinds. This is the pre-existing port vocabulary; within Task 9's five adapters all kinds are representable.
- `claims_facet.content` is a JSON-array-text string (single rendering rule, `bundle.rs:370-372`); B.3 shows an open string. Fine.

**m10. The command adapter's facet kind is caller-bound with no type-level restraint.**
`CommandObserver` accepts any `FacetKind` (`gauntlet-adapter-observe-command/src/lib.rs:10-15, 84-131`), so a composition root could bind a build command to `FacetKind::Filesystem`. `facet_kind()` remains self-consistent, so the shared suite passes regardless; the misbinding risk sits entirely on the (future) production caller.

## Explicit judgment calls the brief asked for

**Claims covered by the digest vs. claims as verification input — judged spec-consistent.** `VerificationInputs` carries `observation_digest` (`input.rs:84-92`), and that digest is a function of the claims (pinned by test, `input.rs:314-335`). This is not an I2 leak: §5.3.6 *requires* `ComparisonRecord` to carry `observation_digest`, §12.4 defines the digest over the whole normalized bundle (which B.3 includes `claims_facet` in), and a SHA-256 value is one-way — claims text cannot be recovered from it, and the only residual channel is bundle-equality testing, which is not verification semantics. The artifact's own tests document precisely this distinction (`input.rs:276-311`: under a claims swap, every input except the digest identifier is unchanged). The distinction is spec-consistent and honestly engineered.

**Filesystem walk exit 0 despite recorded errors — judged spec-consistent.** The instrument's exit status reports the *observation's* success, not reality's; unreadable entries become manifest `error` lines and counted errors in the summary (`gauntlet-adapter-observe-filesystem/src/lib.rs:145-158, 271-313`). Only an inability to run at all is an `ObserverError`. This is the correct P3 polarity and the opposite of defaulting to success.
