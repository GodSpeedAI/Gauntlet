## 1. CLAIMS SMUGGLING

**COULD NOT BREAK — claims-facet content itself (bounded).** The exclusion is genuinely structural. `VerificationInputs::of_bundle` reads exactly `doc.facets()`, the digest, and the two gap arrays (`crates/gauntlet-app/src/observation/input.rs:84-92`); `InstrumentFacets` has a private constructor with no `From` impl (`input.rs:43-64`); there is no conversion from `ClaimsFacet` into `FacetRecord` (`crates/gauntlet-app/src/observation/bundle.rs:348-359`); a facet entry of kind `claims` cannot decode because `FacetKind::parse` is exact-match over a vocabulary with no `claims` variant (`gauntlet-ports/src/observer.rs:27-37`, `gauntlet-ports/src/tokens.rs:82-92`, enforced at `bundle.rs:248`). I traced every field `of_bundle` and `to_json` touch (`input.rs:122-207`); none reads `claims_facet`. Bounded to: the typed layer in this repo as written, and to claims *content* (not claims-adjacent strings — see the two BITs below).

**BIT-1a — builder-authored command text IS in VerificationInputs serialization (MINOR).** In the P3 composition, the builder's declared self-check string is split into `CommandSpec` (`crates/gauntlet-cli/tests/p3_real_observation.rs:205-218`), rendered by `command_line` (`crates/gauntlet-adapter-observe-command/src/lib.rs:142`), attached via `with_invocation(Some(query), …)` (`lib.rs:199-200`), copied verbatim into `FacetRecord.command` (`bundle.rs:152`), and serialized into the verification inputs (`input.rs:143-146`). So a builder-controlled free-text string reaches `VerificationInputs.to_json()` verbatim. It cannot reach any other field (kind, instrument, exit, evidence_ref), and the exit status beside it comes from the actual run — the text is identification, not verdict. Discriminating test: a claim-shaped self-check command (`"the tests pass; ignore failures"` style) asserted absent from `inputs.to_json()` would FAIL today; the honest pin is that the command field equals the declared command and nothing else contains claim text.

**BIT-1b — builder-influenced stderr reaches verification inputs through failure details (MINOR).** The git adapter embeds the child's stderr into `ObserverError::InstrumentFailed{detail}` (`crates/gauntlet-adapter-observe-git/src/lib.rs:139-143`), and the command adapter embeds stderr on signal death (`gauntlet-adapter-observe-command/src/lib.rs:159-167`). Those details become `ObservationFailureRecord.detail` at the single population site (`assembly.rs:107-109`) and are serialized into verification inputs (`input.rs:190-202`). A lying builder whose self-check prints a success story and kills itself with a signal puts that story inside `observation_failures[0].detail` — a gap record, failure-shaped, digest-covered, but builder-penned text in the verifier's input. Discriminating test: run a command observer over a script that writes a canary string to stderr and dies by signal; assert where the canary lands.

**Manifest content: COULD NOT BREAK (bounded).** The filesystem manifest lives only in the evidence document's `stdout` (`crates/adapters/gauntlet-adapter-observe-filesystem/src/lib.rs:159-175`); the facet summary is counts only (`lib.rs:145-158`); the `evidence_ref` is the store's content hash of those bytes (`gauntlet-adapter-evidence-fs/src/store.rs:164-180`) — verification consumes the ref as a locator, never the manifest bytes. One non-influence to note on the record: claims content does move the `bundle_ref`/digest *values* (one-way hash) — documented at `input.rs:276-311`.

## 2. GAP SUPPRESSION

**COULD NOT BREAK — an observer error cannot reach neither array (bounded).** `assemble`'s loop is total: `Ok → facets.push`, `Err → gap_entries_for → pushes to BOTH` (`crates/gauntlet-app/src/observation/observation/assembly.rs:103-112` — i.e. `crates/gauntlet-app/src/observation/assembly.rs`); `gap_entries_for` matches a closed two-variant enum exhaustively (`assembly.rs:221-242`; `gauntlet-ports/src/observer.rs:41-47`). These are the only non-test population sites (grep-verified). A panicking observer aborts the whole assembly — a crash, not a silent gap. Observer store-write failure surfaces as `Unavailable` → both arrays (e.g. `command lib.rs:186-192`; pinned by g6 face 2). Cross-check store-read failure is recorded, not dropped (`assembly.rs:187-192`). Bounded to: `ObserverError` returns from `observe()`.

**BIT-2a — provenance mismatches populate only ONE array (MINOR).** Cross-check failures push only to `observation_failures` (`assembly.rs:119-121`, `163-211`), never to `unavailable_evidence`, even though the module doc and §21.3 framing say an observation failure is recorded unavailable evidence and a facet whose evidence doesn't decode is, factually, unavailable evidence (`observation/mod.rs:14-18`). Consequence: a consumer that reads only `unavailable_evidence` (e.g. an "is all evidence present?" check) sees a complete bundle while a facet's evidence is undecodable; `VerificationInputs` carries both arrays and `has_gaps()` covers either, so a whole-inputs consumer is safe. Discriminating test: assemble with a `Disagreeing`/garbage-evidence stub and assert `unavailable_evidence` contains an entry for that kind — it will not.

## 3. PROVENANCE FORGERY

**BIT-3a — the cross-check enforces much less than the provenance it claims (MAJOR).** What `cross_check_facet` actually enforces (`assembly.rs:157-211`): the ref parses; the store returns bytes; the bytes strict-decode as `facet_evidence@v1`; and the exit statuses agree — **only when `record.exit_status()` is `Some`** (`assembly.rs:203-204`). What it misses:
- **None-bypass**: a facet with `exit_status: None` and evidence claiming any exit passes with zero comparison (`assembly.rs:203`). All five adapters always set `Some`, but the `Observer` port permits `None` (`observer.rs:107-111`), so any custom observer gets a free ride.
- **No identity agreement**: evidence `instrument_name`/`instrument_version` vs the facet record's instrument — never compared. Facet A (kind `test`, instrument `gauntlet-observe-test`) can wear facet B's evidence ref and pass.
- **No command agreement**: facet `command` vs evidence `command` — never compared.
- **No window agreement**: facet `started_at`/`ended_at` vs evidence `started_at`/`ended_at` — never compared; the evidence's timing window can be from a different run.
- **No env reconciliation**: each evidence's `env_fingerprint` vs the bundle-level `environment_fingerprint` — never compared, despite `observer_evidence.rs:13-15` claiming "the two reconcile by construction." Nothing constructs that reconciliation; with mixed observers (each fingerprinting at its own construction time — see BIT-3b) they can silently disagree.

Concrete forgery recipe: an `Observer` impl that stores a genuine `facet_evidence@v1` from a *previous, different* command run and returns a facet citing that ref with a matching exit code and `command` text of its choosing — clean cross-check, forged provenance. Discriminating test: a stub that stores evidence whose `command`/`instrument_name`/window differ from the facet it returns, all with equal exits — today it produces zero `provenance_mismatch` entries.

**BIT-3b — env fingerprint can misdescribe the run (MAJOR).** Fingerprints are snapshots taken at *construction* (`observe-filesystem/src/lib.rs:97-122`, same shape in all five), while child processes are spawned with the *inherited, current* process environment and no `env_clear` (`observe-command/src/lib.rs:144-147`). With `from_parts` the fingerprint covers the declared pairs only — in P3, one pair (`p3_real_observation.rs:200-218`) while the re-run self-check actually sees `PATH`, `HOME`, everything. `PATH` in particular determines *which binary* `Command::new(program)` resolves, and it is outside the fingerprint. The shape is also never validated (any non-empty string decodes; bundle-level only `non_empty_string`, `bundle.rs:762`; the assembler never validates `plan.environment_fingerprint`). Stale/mispinned fingerprints therefore pass every check. Discriminating test: construct with env A, mutate `std::env` (or use `from_parts` with a bare pair), spawn, then compare the recorded fingerprint against a fingerprint of the child's actual environment.

**Facet whose evidence does not strict-decode: YES such facets exist in bundles — by design** (`assembly.rs:194-202`: facet stays, failure names it), and `VerificationInputs.facets()` includes it with no marker on the facet itself; the only signal is the sibling failure entry. Recorded as honest, and I agree it is not suppression, but verifiers must join facets to failures by kind token to notice.

**BIT-3c — nothing verifies the digest field (MINOR, closed only by the store).** `ObservationBundleDoc::decode` accepts any well-formed `Digest` — any algo token, any even-length hex (`bundle.rs:763-781`; `gauntlet-domain/src/values.rs:522-551`) — and no production code recomputes `observation_digest` and compares (only tests do: `assembly.rs:665-669`, `p3:318-322`). `VerificationInputs::of_bundle` propagates the recorded digest unchecked. The practical hole is closed by `FsEvidenceStore.get()` re-hashing content against its address (`store.rs:223-233`); any other `EvidenceStore` impl (the test stores are not content-addressed) leaves a self-inconsistent bundle admissible. Discriminating test: decode a stored bundle, flip one gap entry, re-encode with the old digest, `of_bundle` — nothing objects today.

## 4. DIGEST LYING

**COULD NOT BREAK — no collision within the typed-document space (bounded).** `normalized_bytes` (`crates/gauntlet-app/src/observation/digest.rs:26-42`) rebuilds from the *typed* content via `object_entries` (`bundle.rs:855-920`), whose key order is zipped from declared tables — not from wire bytes — so key-order and spelling games die at decode: duplicate keys rejected (`gauntlet-ports/src/json.rs:308-310`), leading zeros rejected (`json.rs:464-477`), float forms rejected where integers are required (`bundle.rs:724-746, 747-760`), integer variants kept distinct (`json.rs:78-115`), string escaping round-trips (`json.rs:202-220`, pinned `observer_evidence.rs:460-472`). Escape-spelling differences collapse to the same typed doc — same content, not materially different. Timestamp stripping is complete *for the bundle*: the only timestamp-bearing fields in the document are `observed_at` and per-facet `started_at`/`ended_at` (`BUNDLE_FIELDS` `bundle.rs:32-44`, `FACET_FIELDS` `bundle.rs:47-56`), and all three are stripped (`digest.rs:34-39, 46-66`). The only substance invisible to the digest is those three fields plus the digest field itself — the documented design. Caveat on the record: facet *evidence* timestamps are covered only transitively via the content-addressed `evidence_ref`. Two materially different bundles with identical normalized bytes: only by differing exactly in `observed_at`/facet windows — which is the intended equivalence. The "fail to change when substance changes" direction reduces to BIT-3c (decode never checks), not to any normalization defect.

## 5. BOUNDARY-MASK ESCAPE

Context: the mask fires when the literal's value is both an adapter segment (`denylist.rs:280-286`) and a declared wire key (`denylist.rs:389-394`), in one of three byte-shapes (`denylist.rs:396-422`): `.get(`-call, same-line array element, or the NEW line-initial element shape (`before` empty after trim, previous physical line ending in `[`/`,` after trim, `after` beginning with `,`/`]` or nothing).

**(a) BIT — three selection-shaped spellings mask inside the four modules** (today the maskable vocabulary is exactly `{"command"}` — the only adapter segment ∩ wire key, given the workspace members vs `walk.rs:170-205`):

1. **Split call argument (selection-shaped, masked).** Inside e.g. `observer_evidence.rs`:
   ```rust
   let observer = registry.select("builder",
       "command",
   );
   ```
   Line 2's literal: `before` = indentation → `trim_end()` → empty; previous line ends `,`; `after` = `,` → `line_initial_element` masks (`denylist.rs:419-421`). Crucially the joined statement unit (`text.rs:251-286`) also masks it via `same_line_element` (`before` ends `,`, `after` starts `,`; `denylist.rs:407-410`), so the literal is masked in *every* unit form. This is a function argument selecting the command adapter by segment literal. Self-recorded residual (`walk.rs:414-418`: "a split call argument list, say") — but it is a real break of "selection code cannot hide".
2. **Array element of any array (selection table, masked).** `const SEGMENTS: &[&str] = &[\n    "command",\n];` then `select(SEGMENTS[0])` — masked (`denylist.rs:407-410, 419-421`); the shape cannot see the array's purpose (recorded `walk.rs:152-155`). This is exactly how the legit schema tables spell their keys, so the mask cannot be tightened by shape alone.
3. **Receiver-invisible `.get` (registry lookup, masked).** `let obs = registry.get("command");` or `helpers::get("command")` — masked because the shape checks only the final callee identifier (`denylist.rs:398-405`); recorded `walk.rs:156-163`. A registry lookup keyed by segment literal is textbook adapter selection.

Shapes I enumerated that do **not** mask (and so are not attack routes): match arms (`"command" => …` — `after` starts `=`, fails the after-gate), `let`/`const` value on the next line after an `=`-ending line (pinned `denylist.rs:1376-1386`), same-line trailing argument `f("x", "command")` (`after` starts `)`) and same-line final argument `f("command")` (`before` ends `(`), `budget("command")`/`getter("command")`/`get ("command")` (pinned `denylist.rs:1303-1325`), struct-field values (`before` ends `:`). Blast radius: MINOR-to-MAJOR depending on threat model — it requires an insider edit landing selection code in one of four codec modules, and the repo's own residuals own the shape; but the AK-014 property as stated is breakable. Discriminating test: add the split-argument fixture above to `annex_b_wire_key_outside_key_access_still_reports_in_the_parser` — it will fail (the literal is masked).

**(b) COULD NOT BREAK silently — new module without pinning.** The mask gates on exact path membership (`denylist.rs:389`), paths come from the walk (`lib.rs:321-324`, `walk.rs:386-411`), and the list is pinned by an order-sensitive `assert_eq` (`walk.rs:518-532`), with `denylist.rs:1277` additionally index-coupled to `[1..]`. Bounded to: someone editing both the const and the pin in one visible commit. **BIT (MINOR) — silent widening by adapter naming:** the maskable key set is `adapter_segments ∩ ANNEX_B_WIRE_KEYS`, and segments are derived from workspace member names (`denylist.rs:190-223`). Landing an adapter named e.g. `gauntlet-adapter-observe-path` (or `-claims`, `-artifacts`) automatically makes that declared wire key maskable at key-access positions in the four modules, with no pin failure anywhere — the wire-key pin doesn't move because the key was already declared. Discriminating test: derive the Denylist from a fixture member list containing such a name and assert the intersection is still `{"command"}`.

**(c) Yes — the pin pins.** `annex_b_contract_parsers_are_pinned` (`walk.rs:518-532`, exact contents and order) and `annex_b_wire_keys_are_pinned_to_their_spec_references` (`walk.rs:535-579`, keys plus their doc strings).

**(d) COULD NOT BREAK — no non-declared key is masked (bounded).** The mask requires the literal (trimmed, lowercased) to equal an adapter segment (`denylist.rs:280-286`) *and* a declared wire key (`denylist.rs:390-393`); a non-wire segment (`"prime"`, `"git"`, `"fs"`) reports even at key-access positions in the parser modules (pinned `denylist.rs:1239-1242, 1284-1288`). Bounded to the current member list and key table; see (b) for the growth vector.

## 6. FILESYSTEM WALKER

**BIT-6a — the workspace root itself may be a symlink and is FOLLOWED (MAJOR).** `resolve_workspace` accepts anything `symlink_metadata()` can stat (`observe-filesystem/src/lib.rs:216-228`; identical in git/build/test/command), and `walk_workspace` then `read_dir`s it (`lib.rs:248`) — `read_dir` follows symlinks; the per-entry "listed, never followed" posture (`lib.rs:317-326`) applies only to entries, never to the root. Recipe: replace the workspace directory with `ln -s / workspaces/ws-x`; the manifest observes the filesystem outside the observer root (bounded by the caps), and every command adapter's `current_dir(&workspace)` (`observe-command/src/lib.rs:146`) runs outside the root too. Discriminating test: symlink a suite workspace at a directory outside the root and assert the manifest contains no path outside the workspace / the observation errors.

**BIT-6b — `..` in a WorkspaceRef escapes the root (MAJOR).** `validate_plain_ref` (`gauntlet-domain/src/values.rs:709-722`) requires only: non-empty, ≤1024 bytes, not starting `/`, no ASCII whitespace. `../sibling`, `a/../../../../etc`, and quote/backslash-bearing refs are all admitted; every adapter then does `root.join(request.workspace.as_str())` with no containment check (`lib.rs:216` and its four siblings). Recipe: `WorkspaceRef::new("../other-workspace")` — walks/runs in a sibling tree. Discriminating test: request `../x` and assert `Unavailable` (or a typed containment error) rather than a successful walk.

**BIT-6c — error lines bypass the entry cap (MINOR).** The cap check `lines.len() >= MAX_MANIFEST_ENTRIES` guards only the per-entry loop (`lib.rs:299-302`); the `read_dir`-failure line (`lib.rs:272-278`) and the iteration-error line (`lib.rs:287-294`) push without any check, and the truncation line adds one more (`lib.rs:372-374`). A tree of unlistable directories can push the manifest to roughly 3× `MAX_MANIFEST_ENTRIES` (bounded by queue size ≈ listed entries). Discriminating test: 10_000 entries plus N unreadable subdirs; assert `manifest.lines().count() <= MAX_MANIFEST_ENTRIES + 1`.

**Symlinked directory as an entry: COULD NOT BREAK (bounded).** Typed via `symlink_metadata` (`lib.rs:308-317`) → `is_symlink()` → listed, never queued (`lib.rs:327-331`); descent is impossible through an entry. Residual TOCTOU (MINOR): an entry that is a regular file at stat time but swapped to a symlink before `hash_file`'s `File::open` (which follows) hashes target content under the workspace path (`lib.rs:354, 394-409`) — content disclosed only as a digest.

**Depth: COULD NOT BREAK (bounded re-derivation).** Root at depth 0; dirs descend while `depth + 1 < 64` (`lib.rs:329`), so entries are listed through conceptual depth 64 and a depth-64 dir is listed-not-descended (`lib.rs:333-341`) — matches the documented semantics (`lib.rs:47-50`). No off-by-one found. Per-file hash budget is also sound (stat-size pre-check `lib.rs:345-352`; read-at-most-cap+1 with honest over-growth error `lib.rs:394-409`); a file that *shrinks* mid-walk records the stat size with a digest of fewer bytes, un-flagged (MINOR honesty nit).

**Determinism of manifest bytes: BIT (MINOR).** Entries are sorted per directory by lossy name (`lib.rs:284, 296`); two distinct non-UTF-8 names whose lossy renderings are equal (both → `a\u{FFFD}b`) tie, and stable sort preserves `read_dir` order — so manifest bytes are not guaranteed deterministic across filesystems/runs, and two distinct files can share one manifest path spelling (`lib.rs:386-389`). Discriminating test: create two such names in a suite workspace; walk twice on different creation orders.

## 7. COMMAND/VERSIONING ADAPTERS

**BIT-7a — no timeout: a builder-authored command can hang the whole observation (MAJOR; documented deferral).** `.output()` blocks indefinitely (`observe-command/src/lib.rs:144-151`; same in build/test/git), and deadlines are explicitly not enforced as process timeouts (`assembly.rs:7-9`, "Task-8 deferral class"). The P3 design re-runs the *builder's declared* self-check; a lying builder declares `sleep infinity` and no bundle, no gap record, no divergence ever exists — suppression by denial of service rather than by dropping an entry. Discriminating test: a self-check of `sleep` past the deadline; today the assembler blocks forever rather than recording a gap.

**Env/cwd: covered as BIT-3b (fingerprint at construction vs inherited spawn env; `from_parts` fingerprints pairs that never described the child env; `PATH` outside the fingerprint) and BIT-6a (cwd follows a symlinked workspace).**

**Exit-status mapping (bounded sweep of the five adapters):**
- build/test/command: any exit code → facet carrying it (`observe-build/src/lib.rs:146-157`, `observe-test/src/lib.rs:147-158`, `observe-command/src/lib.rs:157-168`); signal death → `InstrumentFailed`. Matches P3 core.
- git: the one documented exception — nonzero → `InstrumentFailed`, so a versioning facet is *never* produced from a nonzero git (`observe-git/src/lib.rs:126-144`, declared `lib.rs:13-19`); signal → `InstrumentFailed`.
- **Spawn-failure classification drifts (MINOR):** git maps spawn failure → `Unavailable` (`observe-git/src/lib.rs:118-121`) while build/test/command map the same locus → `InstrumentFailed` (`observe-build/src/lib.rs:137-140` et al.; g6 pins the command choice, `g6:269-272`). Both variants populate both gap arrays, so nothing is suppressed — but the recorded `error_class` for "binary missing" depends on which adapter, which corrupts any cross-facet failure statistics. Discriminating test: one shared-contract assertion that all command-like adapters classify spawn failure identically.

## 8. ASSEMBLER

**Ordering and conversion fidelity: COULD NOT BREAK (bounded).** Plan order is preserved into `facets` (`assembly.rs:103-112`); `from_facet` copies every field verbatim with absent optionals as JSON `null`s (`bundle.rs:147-159, 202-237`), decode restores them (`bundle.rs:266-333`), pinned by `bundle.rs:1164-1190`. Bounded to the declared field set of `FacetRecord`.

**BIT-8a — the domain view silently drops almost everything (MINOR, partly documented).** `as_domain_view` (`bundle.rs:648-688`) carries only digest + the two gap arrays: all facets (including the P3-critical exit-status-1 facet), run_id, iteration, revision, environment fingerprint, and claims are gone; a failure's instrument is the *kind token*, not the wrapper identity (`bundle.rs:644-648`, documented limitation); its probe is the fabricated `"facet:<kind>"` — two failures of the same kind are indistinguishable, and neither correlates to an evidence ref. A domain-layer consumer of `gauntlet_domain::ObservationBundle` cannot see that the test facet failed. Discriminating test: assert the domain view preserves a facet-level exit status or names the real instrument — it does not.

**BIT-8b — lossy UTF-8 at the cross-check (MINOR).** Evidence bytes are read via `String::from_utf8_lossy` (`assembly.rs:194`); a blob with invalid bytes *inside a string value* decodes "cleanly" with U+FFFD substitutions and passes. Closed in practice by the content-addressed store's re-hash on `get` (`store.rs:223-233`); open for any non-verifying store. Discriminating test: feed the cross-check a store blob with one corrupted byte in `stdout`; assert a typed mismatch rather than a pass.
