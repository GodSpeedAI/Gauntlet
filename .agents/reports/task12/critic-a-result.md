## CRITICAL

### C1. §11.6 terminal mislabel: governance-blocked runs are reported `budget_exhausted`; `blocked` never occurs; no ticket (controller.rs:946-959)
`plan_and_dispatch` ends with:
```rust
if !admitted && state.in_flight.is_empty() {
    state.terminal = Some(TerminalState::BudgetExhausted);
}
```
`admitted == false` whenever the plan produced no dispatches — including when the only open unit is ineligible for GOVERNANCE reasons (irreversible per §11.2/§17.1; tier unconfigured; authority-blocked). No budget dimension has breached in that case, yet §11.6's table makes "a budget dimension breached" a required precondition of `budget_exhausted`, and requires the `blocked` terminal to carry an escalation ticket ("≥1 Unit requiring an authority the run cannot exercise; escalation ticket created"). `TerminalState::Blocked` exists in the domain (gauntlet-domain/src/values.rs:260-261) but is never set anywhere in controller.rs; no escalation is submitted on this path. The scheduler's typed `Ineligible` reasons (scheduler.rs:143-189) are discarded by `plan()` (scheduler.rs:545-551), so the loop structurally cannot distinguish "blocked by governance" from "out of budget". Reproduction by reading: an answer key whose only unit is `blast_radius: irreversible` runs to `budget_exhausted` with zero spend and no ticket — a terminal report that misstates the run's cause. This breaks a spec-mandated terminal precondition, though no proof assertion becomes false because of it (P6's exhaustion is genuinely budget-driven and separately asserted).

## MAJOR

### M1. The rounds budget dimension is dead in every shipped path; P6's terminus exists only behind a proof-local meter (§17.4, §11.4 step 5, §11.6)
- The shipped adapter books zero rounds per charge — gauntlet-adapter-meter-memory/src/lib.rs:177-188 ("Payments carry no rounds … the round counter moves only at iteration boundaries"), port-pinned by the shared suite. No shipped composition books rounds.
- The controller's rounds gate reads `state.meter.remaining().rounds == 0` (controller.rs:929-934 and 1846-1848). Under the real adapter `spent.rounds` never moves, so the gate can never fire; additionally `remaining_of` subtracts from the RAW limit (gauntlet-ports/src/budget_meter.rs:127-145), and `charge` refuses past the forward ceiling (budget.rs:557-565), so `remaining().rounds == 0` is unreachable even in principle.
- Meanwhile the loop's own `state.budget.charge(1, …)` per completion (controller.rs:1423-1431) fails with `ControlError::Budget` once past the forward rounds ceiling — so under the bare shipped adapter a long non-converging run returns an Err from `start_run` (crash-shaped) instead of the `budget_exhausted` terminal.
- P6 reaches the clean terminus only through the proof-local `RoundsSupplementedMeter` that books each admitted reservation's round at reserve time (p6_budget_control.rs:62-74, 474-581); the p6 header itself records "no shipped composition books rounds, so the gate cannot fire … recorded as a residual". The in-crate controller tests pass only because their `FakeMeter` books reservation rounds (controller.rs:2854-2878) — also not the shipped adapter. AK-051 is therefore proven against a composition that exists only inside the proof file.

### M2. §15.2 diagnosis through the composed loop is degenerate: hardcoded evidence, hardcoded observation, and a per-phase spend equal to the ENTIRE diagnostic allowance (controller.rs:1685-1718)
`enter_diagnosis` builds `DiagnosticEvidence::default()` then sets `implementation_shaped = true` unconditionally (controller.rs:1698-1702) — through the composed path every diagnosis blames the implementation, the exact default §15.2 forbids ("a loop that only ever diagnoses 'implementation defect' is not diagnosing"; the apparatus facts are only ever set for reference-unavailability). The disconfirming observation is the constant `DisconfirmingObservation { disconfirmed: true }` (controller.rs:1711) — no discriminating test is ever run. And the engine's per-phase spend is the FULL allowance (`DiagnosticSpend { tokens: diagnostic.tokens(), cost_usd: diagnostic.cost_usd() }`, controller.rs:1691-1694), so phase 1 consumes the whole §15.2 budget and phase 2's charge always fails: through the composed controller the cycle can never reach `CorrectionIndicated` and always ends INCONCLUSIVE at phases_completed = 1. The pure `DiagnosticEngine` (diagnosis.rs:601-751) is faithful and well-tested; the composition that reaches it is not.

### M3. §11.5 row 9 / AK-039 is unreachable through the composed controller: the diff comparator's residuals carry no unit attribution (controller.rs:1626-1645, 2111-2127)
The loop feeds the `NonconvergenceDetector` only residuals attributed to a unit — `doc.unit_refs().first().cloned()` (controller.rs:2123) — but the only shipped deterministic comparator constructs every residual with `unit_refs: Vec::new()` (gauntlet-adapter-compare-diff/src/lib.rs:192-205, 216-232, 242-…; `ResidualDoc::new`'s third parameter, comparison_record.rs:220-238). `attributed` is therefore always `None`, the detector never observes, and `enter_diagnosis` can never fire in any composition built from shipped adapters. Both proof headers admit it (p4:162-165 "composed non-convergence detection cannot fire"; p6:78-93 same, deferring to in-crate tests). AK-039's behaviors are pinned only by unit-level tests of the detector/engine (diagnosis.rs tests), not through the composed path.

## MINOR

### m1. §11.4 steps 4–5 run at iteration boundaries, not every tick (controller.rs:1117-1199)
The drain tick performs steps 1–3 (poll, stall detection, answer-key re-read) but never re-verifies the reference digest or re-checks budget inside a tick; those happen in `boundary_verify`/`decide_progress` (controller.rs:766-797, 801-838, 1833-1850). A mutation or breach mid-drain is caught only at the next boundary — eventual, not per-tick, enforcement.

### m2. Four Annex E control settings are REQUIRED, contradicting §8.3 (disposition.rs:100-177)
§8.3: "All are optional; all have defaults; none may be required for a bounded run to start safely", and Annex E lists `GAUNTLET_STALL_TIMEOUT_MS`, `GAUNTLET_RETRY_BASE_MS`, `GAUNTLET_RETRY_MAX_MS`, `GAUNTLET_MAX_ATTEMPTS_PER_UNIT` in the Limits group (spec lines 565-567, 2092). `ControlPolicy::from_settings` refuses to run without all four (typed `RequiredSettingMissing`). Conservative direction (no unsafe default is invented), but a bounded run under defaults alone cannot start, contra §8.3.

### m3. `remaining()` reports raw-limit headroom, not forward-ceiling headroom (gauntlet-ports/src/budget_meter.rs:127-145)
Recorded headroom in `BudgetFacts`/budget rejections (and the §15.1 trace) includes the reserve; the refusal arithmetic itself is correct in the domain. Contributes to M1's dead rounds gate.

### m4. One vacuous assertion in p4's composed AK-037 test (p4_corrective_loop.rs:1454-1459)
`rejected.iter().all(|a| !format!("{:?}", a.reason()).is_empty())` — Debug of an enum variant is never empty; tautological among otherwise genuine assertions.

### m5. Selector fold's loser notes reference the then-incumbent, not the final winner (select.rs:287-321)
A candidate eliminated by a later-displaced incumbent is recorded "not selected over X" where X itself subsequently lost. Each pairwise fact is accurate; the trace slightly overstates its explanatory closure.

### m6. Non-convergence early-return leaves stale residual state (controller.rs:1626-1645)
`enter_diagnosis` returns before `state.open_residuals = …` is assigned; on the `CorrectionIndicated` path the loop continues with the previous iteration's residual set.

### m7. Tier/containment posture is permissive pending Task 14 (controller.rs:921, 1081-1095, 1953-1960)
`dispatch` sends `sandbox_policy: None` with a nominal permission-set ref for every tier, and `dispatchable_tier_capacity` admits `cross_cutting` at the global parallel bound. §17.3's "tightest available real backend" for cross_cutting is not yet composed (Task 14's declared scope, but the tier currently dispatches uncontained). Conjunct 5 also hardcodes the Builder role rather than "the roles the slice needs".

### m8. No operator surface reaches the controller (gauntlet-cli/src/main.rs:19-28)
The shipped binary exposes only `doctor` and `reference`; `run`/`resume` (§20.1, §18.3) do not exist, so the composed controller is reachable only through tests. Task 20 presumably owns this; noted for the reachability ledger.

## Net assessment
The control core (scheduler, selector-as-type, diagnosis engine, disposition table, budget arithmetic) is unusually faithful to the spec text, and P4 is a real composed proof. The composed loop, however, currently mislabels governance blocks as budget exhaustion (C1), cannot reach rounds exhaustion or diagnosis through any shipped wiring (M1/M3), hardcodes its diagnostic facts and observation (M2), never records a selection when actually correcting (M5), and ships no teeth checks (M6). Those are exactly the seams where "the artifact passes its tests" and "the artifact implements the spec" come apart.
