## Honest gaps (declared blindspots and scope boundaries)

1. **Real-network transport is T20.** All stream failure here is deterministic in-process (withheld delivery, reorder, retention expiry, epoch replacement through the injected port). Real target paths — live network loss, half-open connections, real backpressure — are out of scope per the frozen prereg blindspot.
2. **Million-event scale is T21.** Representative in-flight volumes only (tens of events); baseline reconciliation is a full window fold per source, with no incremental-snapshot optimizations, no memory/latency measurements.
3. **Cross-process reality is T24.** Detach/reattach composes T10's adapter model in one process; persistence of the detached presentation state across a real process boundary (serialization, storage) is not implemented — the receipt is an in-memory value, and presentation cursor persistence is explicitly NOT execution recovery (canonical execution lifetime stays with Prime; T24 owns real cross-process resumption).
4. **The workbench minting of generation ids is client-side.** The handshake treats the projection generation as the workbench's own reconciled view identity; if a future owning source declares its own stream generations, the mapping must be strengthened at the source contract (prereg trigger R1 — no heuristic was needed; ordering uses only source-declared sequences).
5. **Rendering is not exercised.** Degraded/resync visibility is model-level observable state (`state`, `degradedReasons`, `stateLog`, `onStateChange`); rendering it into the TUI chrome is the T12/T18 surface. No pixels were asserted here.

## What the independent adversarial verifier should attack hardest

1. **The reconnect baseline contract.** Reconnect always lays the FULL baseline through the live watermark onto the fresh (empty) T06 generation; the persisted cursor decides only validation and reporting. Attack whether any path advances a cursor past an event that was never applied to the store — especially interleaving `poll()` with `reconnect()` mid-handshake, or delivering frames DURING a resync.
2. **The buffering state machine.** Interleave gaps across TWO sources, close one gap while the other stays open (state must stay `buffering` until no gap is awaited AND nothing is buffered), duplicate/duplicate-then-fill sequences, and overflow exactly at the capacity boundary. Check `degradedReasons` never lies (empty while any gap is awaited; populated exactly while `buffering`/`resyncing`).
3. **Detach/reattach trust boundaries.** Feed a FORGED `DetachedPresentationState` (cursor from a foreign epoch, sequence ahead of the watermark, sequences claiming events that were never authoritative) into `reattach` and verify it is either validated-away (fresh baseline) or provably cannot fabricate projection state; verify the receipt's `cancel_calls_issued: 0` is structural (the type is `0`, not a runtime value) and that no detach path can reach an adapter mutation.
4. **Convergence comparator blind spots.** `projectionDifferences` compares semantic rows + provenance but ignores `updated_at` and generation ids; attack whether two stores with DIFFERENT fold orders but equal final rows (last-write-wins collisions across sources) can pass as "converged" while a later increment diverges.
5. **The kill-after-acceptance leg against the real Rust surface.** In-suite it terminates in the canonical-surface stub; the verifier should re-drive the same boundary through `gauntlet serve` (`HttpOperatorActionRoute`) to confirm the typed `outcome_unknown` → §16.3 re-entry behavior on the real write path.

### MAJOR (CLOSED — live-streams.ts `reconcileSource`, baseline path): silent cursor advance past a store-refused baseline event

- **Verified defect**: `applyToGeneration`'s false return was IGNORED during baseline reconciliation. A store-refused event (the refusable class: an unattributable `focus_changed`) was skipped, the tracked cursor advanced to ITS sequence, and `applied_events` overcounted (verifier probe E9: claims 2, store received 1) while state stayed `live` with empty `degradedReasons` and zero resyncs — contradicting this evidence's REQ-DATA-004 claim ("the tracked source position advances only after the store admits the frame") and REQ-SYNC-001 ("never silent cursor advancement") on exactly the path the evidence's verifier-guidance invited attackers to. The identical refusal on the LIVE path correctly triggered the visible `store_refusal` resync.
- **RED-first regression**: `src/reconnect-races.test.ts` — "correction round 1 (verifier E9, MAJOR): a store-refused event IN THE BASELINE is counted, reasoned, and visibly degraded — never a silent advance". Confirmed RED against the pre-fix code (failed on `applied_events` overcount and absent refusal reporting), then GREEN after the fix. The suite went 3→4 tests, 73→94 expect() calls.
- **Fix (verifier-recommended shape adopted)**: on the baseline path a store-refused frame is never silent:
  1. `SourceReconciliation` gains `refused_events: number` and `refusal_reasons: readonly string[]` (the store's typed reason per refused baseline event, in fold order); `applied_events` now counts ONLY store-admitted events.
  2. The client records each refusal as a `BaselineRefusal {generation_id, source_id, sequence, cursor, reason}` (new public `refusals` getter, reset per generation) and surfaces them persistently in `degradedReasons` as `baseline_refusal:<source>:sequence=<n>:<reason>` while the generation that re-baselined over them is live — the hole is visible, not smoothed over.
  3. The tracked position marks the refused frame **consumed-and-refused** (it advances to the refused frame's sequence, now visibly qualified by the reported refusal). Rationale: a position frozen before the refusal would livelock gap detection — the source re-serves the identical refused frame forever, so every subsequent live event would buffer as an unfillable gap, overflow, and resync into the same refusal, looping. `applyToGeneration` now returns the store's full admission result so the typed reason is preserved at both call sites; the LIVE path is unchanged (identity-checked refusals still trigger the visible `store_refusal` resync, and the resync's fresh baseline then reports the persistent hole once instead of looping).
- **What changes in verifier probe E9** (the probe file is the verifier's; not edited by this builder — the corrected expectations are codified in the regression test above and demonstrated in a corrected copy run from /tmp, `e9-corrected.test.ts`, 1 pass / 0 fail):

  - Assertion at extended-attacks.test.ts:611 `expect(gLeg?.applied_events).toBe(2)` now receives **1** — the overcount WAS the defect.
  - Assertion at ~line 614 `expect(client.degradedReasons).toEqual([])` now receives the single `baseline_refusal:gauntlet:sequence=2:…` entry — the silence WAS the defect.
  - All other E9 expectations still hold unchanged: position sequence 2 / cursor `mintOpaqueCursor(2)` (consumed-and-refused), exactly 1 gauntlet store trace, state `live`, `resyncCount` 0 (no resync loop), `focus` stays null (no invented row), the next live event applies normally, and the same refusal delivered LIVE still triggers the visible resync.

### Trigger-records (verified by the verifier, NOT fixed in this round — recorded for the orchestrator)

1. **`degradedReasons` is recomputed only on state TRANSITIONS** — untruthful while the connection STAYS in `buffering`: a second gap opened while one is already open is invisible in the list (E3: two gaps open, only gauntlet's named), and after a partial drain the expected value can go stale (E3b: the reason names an already-applied `expected` while a real later gap remains). Functional behavior (buffering, ordered drain, convergence) is correct; the reason list is a stale projection of gap state.
2. **Listener re-entrancy mid-handshake desyncs observability** (E1b): a `stateListener` that calls `reconnect()` during the `connecting` transition leaves `client.generationId` pointing at the INNER generation while `lastHandshake` reports the OUTER one. Self-healing: the desynced subscription's first delivery is store-refused and drives a visible resync; convergence with the authoritative fold is preserved.
3. **Forged persisted cursors with a matching epoch validate as `"valid"`** (E5-B/C): cursor authenticity is unverifiable against opaque cursors; epoch-mismatched and retention-impossible forgeries are caught, and even a well-formed forgery cannot fabricate projection state (positions are always rebuilt from actually-applied events, convergence holds) — but the `"valid"` label for a forged-yet-plausible cursor is reporting-level only.
4. **`reconcileAll` leaves orphaned buffered frames** (E4): frames buffered under the previous generation are cleared on RESYNC but survive a reconnect, where they can never apply (their generation gate plus the new baseline's advanced position make them permanently inert) until a resync or close clears them. Bounded by `maxBufferedFrames`; no projection effect.

### Informationals (no action required this round)

- **Generation ids are client-local.** Two clients minting identical generation ids (e.g. the default minter) can pass each other's CURRENT-generation frames through the generation gate (E8-sameid: an injected frame APPLIES); cross-client corruption is still prevented by the sequence/epoch/ordering gates, and distinct-minter deployments are unaffected. A shared deployment should mint globally unique generation ids.
- **`projectionDifferences` compares snapshots only.** Cross-source last-write-wins collisions ARE detected (provenance differs), but stores whose final rows and cursors match while their audit traces differ (one applied an intermediate update the other never saw) report converged (E6 blind spot B) — trace-level divergence is invisible to the comparator.
