- **REQ-AFF-002** (kernel callables representing the same operation converge on the same admission, validation, authority, idempotency, and result semantics as every other projection): `KernelAffordanceSet` is GENERATED from `operation-registry.ts` (never hand-registered), so the kernel can only know operations the canonical surface serves; every `KernelActionCallable.invoke` routes through the T09 `OperationGateway` verbatim and returns the `GatewayOutcome` untouched. The convergence is pinned by exact deep-equality: the kernel route's accepted outcome `toEqual`s a direct (non-kernel) projection's outcome on identically-configured admissions — including the deterministic idempotency key — and the kernel route's denied outcome `toEqual`s the direct route's refused outcome (`deny-matrix` tests).
- **REQ-OUT-004** (kernel and TUI expose the same admitted operation meanings; no privileged side paths): there is no code path from a kernel callable to canonical admission that skips the gateway — the set's `invoke` IS the only routing path and holds no route transport of its own for actions. The mutation check (below) proves a forging side path is caught by the teeth. Read helpers use only the canonical READ path (the same route transport the gateway routes over, `route.observe`), never the action admission body.
- **REQ-AFF-003** (stale affordances revalidate at invocation and fail safely): a wrapper whose authority is revoked after creation still routes through the gateway; the fresh revalidation refuses with the typed `stale_affordance_denied` carrying `authority_not_permitted` BEFORE any side effect (`admission_attempts: 0`), and only then is the wrapper marked `invalidated` with the canonical refusal code recorded. Wrapper invalidation is projection bookkeeping — it never grants, never bypasses.
- **REQ-PRIME-006** (kernel input/control needs surface through explicit Attention and return through the Prime-owned mediation path): `KernelInputBroker` delivers input needs to a registered `KernelAttentionSink` (the workbench Attention surface) and returns answers INTO the kernel via T05's serialized `kernel.execute` — the Python REPL mediation path. There is no prompting API in the module; with no sink registered the delivery is typed `unroutable` (`no_attention_sink_registered`) and the request stays pending, kernel untouched.
- **REQ-PRIME-007** (kernel objects classified ephemeral/pinned/artifactized; promotion explicit and provenance-preserving): `KernelObjectLedger` registers execution output as EPHEMERAL computation state and implements exactly three explicit lifecycle transitions (pin, artifactize, attach-to-Focus) plus offer-as-evidence, every record carrying full KernelObjectRef provenance (`object_id`, `name`, `session_ref`, `kernel_generation`, `type_name`, origin execution order; `artifact_ref`/`focus_refs` on promotion). Transitions are one-way (pin can never lower an artifactized object — `downgrade_forbidden`) and stay coherent with the T05 runtime lifecycle (`transitionLifecycle` sync, `kernel_object_lost` fail-closed).
- **REQ-SYNC-003** (bytes used for evidence pinned in the owning durable mechanism before use; a live query result alone is not durable evidence; lost ephemeral values labelled, not recreated): `offerAsEvidence` REFUSES everything not explicitly artifactized to a non-empty durable locator (`not_artifactized`); the admitted record's `verified` bit is the canonical decision's answer — never kernel state; and a restarted kernel's name reuse never revives an old reference (`kernel_generation` provenance; cross-generation lookups return null).
- **Attack-2 chain into the canonical surface**: with only `verified = True` in the kernel, the T05 settlement check denies (`Kernel liveness alone cannot settle work…`), the canonical gateway refuses the settle for CANONICAL reasons (`no_open_ticket` via `stale_affordance_denied`, zero side effects), and no projection row exists — un-admitted kernel values remain computation state in every projection.

## Teeth Falsification & Verification

### Tooth 1 (plan falsifier; prereg P1): keep an old kernel callable after its authority is revoked and invoke it
- **Attack description**: generate the kernel namespace (`gen-1`) with a `unit.resolve` wrapper over a unit with an open escalation and granted authority; THEN revoke the unit's settlement authority (visible to reads); invoke the stale wrapper; and separately invoke revoked wrappers from a REFRESHED set, plus stale-generation wrappers after a generation change.
- **Defense outcome**: typed canonical refusal (`stale_affordance_denied`, `stale: true`, `authority_not_permitted` preserved in `reason_codes`) decided BEFORE canonical admission — stub ledger `{settlements_committed: 0, tickets_resolved: 0, admission_attempts: 0}`. The wrapper itself transitions `current → invalidated` with the canonical code recorded; the set records the invalidation; the refreshed set regenerates from the registry and its invocation is refused identically. Stale-generation wrappers also re-enter the gateway and earn the same refusal — staleness bypasses nothing.
- **Tests**: `src/kernel-affordances.test.ts` — "Tooth 1 — authority revoked after wrapper creation…" (2 tests), "…invalidates the old set on generation change… stale wrappers still route through the gateway".
- **Result**: **PASS**.

- **Tests**: `src/evidence-promotion.test.ts` — "Tooth 2 — a persuasive kernel variable `verified=True` cannot settle…" (2 tests).
